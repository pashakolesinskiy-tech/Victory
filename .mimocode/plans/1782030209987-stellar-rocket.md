# Bug Fix: Question values reset to 100 when adding new question

## Root Cause

CSS class mismatch between the editor UI and the save logic:

- **`ui.js:227`** — value inputs are created with class `q-value-input`
- **`editor.js:10`** — save queries `.q-value`

Since `.q-value` never matches any elements, `updateQuestion()` is never called for the value field. The data model keeps the old value, so when `openEditor()` rebuilds the editor after adding a new question, it reads from the data model and all user-edited values revert to their original state (100 for added questions).

## Fix

**File: `editor.js:10`**

Change `.q-value` to `.q-value-input`:

```js
// Before:
document.querySelectorAll(".q-value").forEach(inp=>{ ... });

// After:
document.querySelectorAll(".q-value-input").forEach(inp=>{ ... });
```

This is a one-line fix. The `.q-value-input` class matches what `ui.js:227` creates.

## Verification

1. Open the app, edit a quiz
2. Add a new question, change its value to 300
3. Add another question — the first question's value should remain 300 (not reset to 100)
4. Save and verify values persist after reopening the editor
