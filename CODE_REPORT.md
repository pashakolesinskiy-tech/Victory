### 5.1. Хранилище медиа — IndexedDB (строки 482–548)

**Паттерн**: IIFE (Immediately Invoked Function Expression), возвращает объект с 4 методами.

**Константы**:
- `DB_NAME = 'svoya_media_db'` — имя базы данных
- `STORE_NAME = 'media'` — имя хранилища объектов

**Переменные**:
- `db` — ссылка на открытое соединение с IndexedDB

**Методы**:

| Метод | Строки | Вход | Выход | Описание |
|---|---|---|---|---|
| `open()` | 487–504 | — | `Promise<IDBDatabase>` | Открывает/создаёт базу IndexedDB версии 1. В `onupgradeneeded` создаёт objectStore `media` с `keyPath: 'id'`. |
| `ensureDB()` | 506–509 | — | `Promise<IDBDatabase>` | Обёртка: если `db` уже открыта — возвращает её, иначе вызывает `open()`. Ленивая инициализация. |
| `saveMedia(id, blob)` | 511–521 | `string`, `Blob` | `Promise<void>` | Сохраняет медиа-объект в IndexedDB через `store.put()`. |
| `getMedia(id)` | 523–534 | `string` | `Promise<Blob\|null>` | Извлекает Blob по ID. Возвращает `null`, если запись не найдена. |
| `deleteMedia(id)` | 536–545 | `string` | `Promise<void>` | Удаляет запись по ID через `store.delete()`. |

**Формат ID медиа**: префикс `db:i_` (изображение) или `db:v_` (видео) + `Date.now()` + `_` + `Math.random().toString(36)`.

### 5.7. Отрисовка игрового поля (строки 734–758)

| Функция | Строки | Описание |
|---|---|---|
| `renderGameGrid(quiz)` | 734–758 | Строит таблицу Jeopardy: категории — заголовки столбцов, баллы — ячейки. Использует `Math.max(...cats.map(c=>c.questions.length))` для определения количества строк. |

### 5.8. Модальное окно вопроса и таймер (строки 760–864)

| Функция | Строки | Описание |
|---|---|---|
| `openQuestion(catIdx, qIdx, value)` | 760–844 | Открывает модалку с вопросом. Загружает медиа (3 типа), заполняет данные, настраивает таймер. |
| `startTimerModal()` | 845–862 | Запускает обратный отсчёт. При достижении 0: помечает вопрос как использованный, переходит к следующей команде, закрывает модалку. |
| `closeModalAndRefresh()` | 864 | Очищает интервал таймера, скрывает модалку, сбрасывает `activeQuestionData`, перерисовывает UI. |

**Логика загрузки медиа в `openQuestion()`** (строки 772–831):

| Тип медиа | Условие | Обработка |
|---|---|---|
| IndexedDB (локальный файл) | `media.startsWith("db:")` | Извлекает Blob из `mediaDB.getMedia()`, создаёт `URL.createObjectURL()`, определяет тип по префиксу `db:v_` или `blob.type` |
| YouTube | URL содержит `youtube.com/watch` или `youtu.be` | Парсит video ID, создаёт `<iframe>` с embed-ссылкой |
| Видео (URL) | URL заканчивается на `.mp4/.webm/.ogg/.mov/.avi` или начинается с `data:video/` | Создаёт `<video>` с контролами |
| Изображение (URL) | Все остальные случаи | Создаёт `<img>` |

**Обработка ошибок медиа**:
- Если файл не найден в IndexedDB: очищает `question.media`, сохраняет, показывает предупреждение
- Если видео/изображение не загрузилось: скрывает элемент, показывает сообщение об ошибке

**Таймер**:
- Конфигурируется через `#globalTimerSecMenu` (по умолчанию 30 секунд)
- При истечении времени: вопрос помечается как использованный, ход переходит, показывается `customAlert`

5. Сохраняет Blob в IndexedDB с префиксом `db:v_` (видео) или `db:i_` (изображение)
6. Сохраняет `mediaId` в поле `question.media`

### 5.12. Инициализация (строки 1108–1138)

| Функция | Строки | Описание |
|---|---|---|
| `init()` | 1108–1138 | Точка входа приложения. Выполняется при загрузке `<script>`. |

**Порядок инициализации**:
1. Открывает базу IndexedDB (`mediaDB.open()`)
2. Загружает викторины из `localStorage` (или создаёт демо)
3. Загружает сессию из `localStorage` (или инициализирует defaults)
4. Рендерит выпадающий список викторин
5. Рендерит игровое поле и команды
6. Привязывает обработчики ко всем UI-элементам:
   - Меню: открытие/закрытие, выбор викторины, создание/редактирование/удаление, бэкап/восстановление
   - Команды: добавление, сброс прогресса
   - Вопрос: запуск таймера, показ ответа, правильный/неправильный ответ, закрытие
   - Редактор: сохранение, закрытие, добавление категории

## 7. Рекомендации по улучшению

### 7.1. Архитектурные

| # | Проблема | Рекомендация | Приоритет |
|---|---|---|---|
| A1 | Весь код в одном файле (1141 строк) | Разделить на модули: `mediaDB.js`, `state.js`, `ui.js`, `editor.js`, `game.js`. Использовать ES-модули или хотя бы отдельные `<script>` файлы. | Высокий |
| A2 | Глобальные переменные (`quizzes`, `currentTeams`, и др.) | Ввести объект состояния (state store) или паттерн Module. Инкапсулировать состояние и предоставить API для его изменения. | Высокий |
| A3 | Нет разделения данных и представления | Ввести простой MVC/MVP: данные (модель), логика (презентер), DOM (представление). Сейчас бизнес-логика смешана с DOM-операциями. | Средний |

### 7.2. Качество кода

| # | Проблема | Рекомендация | Приоритет |
|---|---|---|---|
| Q1 | Нет линтера | Подключить ESLint с конфигурацией для браузерного JS. Исправить предупреждения. | Высокий |
| Q2 | Нет типизации | Рассмотреть JSDoc-аннотации для ключевых структур данных (Quiz, Question, Team) или переход на TypeScript. | Средний |
| Q3 | `==` вместо `===` везде | Заменить все `==` на `===` для строго сравнения. Встречается ~20 раз (строки 650, 666, 670, 693, 897, 999, 1002, 1046, 1062, 1064, 1091, 1119). | Средний |
| Q4 | Длинные строки (до 500+ символов) | Разбить длинные строки, особенно в `renderTeamsPanel()`, `init()`, `deleteCurrentQuiz()`. | Низкий |
| Q5 | Смешанный стиль: `let`/`const`/`var` нет, но `let` используется для переменных, которые не меняются | Использовать `const` для всех переменных, которые не переназначаются. | Низкий |
